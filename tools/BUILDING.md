# Build and offline validation

The repository name does not broaden device support. The current code still targets **Samsung QA75QN90BAJXXZ**, the observed firmware **1710 / `T-PTMUABC-REL-202509042046`**, and the exact four firmware fingerprints embedded in the source. Keep those guards and the original-baseline checks in place when working on this code.

## Build prerequisites

- Install the **.NET SDK 6.0.428** from Microsoft's [.NET 6 download archive](https://dotnet.microsoft.com/en-us/download/dotnet/6.0). This is the compiler version used for the original helpers.
- The repository's `global.json` requires that exact SDK and disables SDK roll-forward. A newer SDK alone will not satisfy this setting. [Microsoft documents SDK selection separately from the target runtime.](https://learn.microsoft.com/en-us/dotnet/core/tools/global-json)
- The helpers target **`netcoreapp3.1`** because the tested TV runs .NET Core 3.1. Building restores the reference pack from NuGet; it does not require running the TV helper on your PC.
- Use **Windows PowerShell 5.1** for the PowerShell test entry point and install **Python 3** for two local launcher fixtures.

`SDK-6.0.428.json` records the original Windows x64 ZIP and Linux x64 tarball URLs and SHA-512 values from Microsoft's [release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/6.0/releases.json). If downloading an SDK archive manually, compare `Get-FileHash -Algorithm SHA512` with the corresponding record before extracting it. The GitHub workflow installs the same exact SDK version through the pinned official `actions/setup-dotnet` action.

## Compile without replacing the delivered helper files

From the repository root:

```powershell
.\tools\Verify-Helpers.ps1
.\tools\Build-Helpers.ps1 -NoCopy
```

Build output goes to `.build/helpers/stage1` and `.build/helpers/stage2`. The build checks the project target and output runtime configuration. It only compiles code; it never invokes a TV helper, SDB, the root tool, or a factory API.

The source layout is:

```text
source/stage1/source/QN90BStage1.csproj
source/stage2/source/QN90BStage2.csproj
source/stage1/tests/QN90BStage1.Tests.csproj
source/stage2/tests/QN90BStage2.Tests.csproj
```

The production projects have no absolute build references. Each managed mock project links only `../source/Core.cs` and `../source/VariantReader.cs`; it does not link `NativeDevice.cs`.

## Replace the helper files after an intentional source change

```powershell
.\tools\Build-Helpers.ps1
```

After **both** projects build, the script copies each `.dll`, `.runtimeconfig.json`, and `.deps.json` into its `engines/stageN` directory and updates that directory's `Helper-SHA256.json`. The manifest is copied last, so an interrupted replacement cannot pass the existing helper hash check. Review the changed source and generated artifacts before redistributing a rebuilt package. Any package-wide checksum list must also be regenerated by the packaging process.

The checked-in helper files are the bytes from the tested package. A rebuild at another checkout path or on another operating system can produce different assembly hashes. The pinned SDK makes the build process repeatable; this repository does not claim a byte-for-byte match with the historical build.

## Run the offline tests

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-Offline.ps1
```

If Python is not on `PATH`, add `-PythonPath C:\path\to\python.exe`. The runner checks the Windows PowerShell version, parses the scripts without executing their application entry points, runs each fixture script in a separate process, and requires **25 Worker tests plus 15 Launcher tests** with zero reported failures. Logs and a machine-readable summary are saved in `.build/test-results` by default.

The Worker fixtures import function definitions and mock all external TV and host processes. Apply and restore state transitions are tested only against those mocks. The Launcher fixtures import functions without starting the GUI and use Python solely to echo an argument vector and generate stdout/stderr data. No TV is needed or contacted.

The existing managed state-machine mocks can be run separately:

```powershell
dotnet run --project source/stage1/tests/QN90BStage1.Tests.csproj --configuration Release
dotnet run --project source/stage2/tests/QN90BStage2.Tests.csproj --configuration Release
```

## GitHub Actions

`.github/workflows/offline-validation.yml` uses a GitHub-hosted `windows-2022` runner, read-only repository permissions, and pinned official actions. It verifies the delivered helper hashes, builds with `-NoCopy`, runs the 40 PowerShell fixtures under Windows PowerShell 5.1, runs the existing managed mocks, and verifies the delivered helper hashes again. There is no deployment, TV address input, dependency installer for TV tooling, application launch, or helper execution in the workflow.

This workflow is a reproducible configuration. Its presence does not assert that a GitHub-hosted run has already passed; consult the repository's actual Actions run for that result.
